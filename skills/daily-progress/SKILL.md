# 每日工作进展生成器

根据 git 提交记录生成结构化的工作进展报告，面向团队汇报使用。

## 参数说明

| 调用方式 | 说明 |
|----------|------|
| `/daily-progress` | 生成日报（前一天 18:00 ~ 今天 18:00） |
| `/daily-progress week` | 生成周报（本周一 18:00 ~ 今天 18:00） |

## 执行步骤

### 1. 收集提交记录

根据传入参数决定模式：

```bash
# 日报（默认）
bash <skill-dir>/scripts/collect-commits.sh

# 周报
bash <skill-dir>/scripts/collect-commits.sh week
```

脚本会输出格式化的 commit 数据，包含 hash、作者、时间、message 和分支信息。

### 2. 解析和分类

脚本输出的每行 commit 格式为：`COMMIT|hash|作者名|作者邮箱|时间|message|refs`

**按 Conventional Commits 前缀分类**（跨所有作者汇总）：

| 类型 | 含义 | 报告标题 |
|------|------|----------|
| `feat` | 新功能 | 新功能 |
| `fix` | Bug 修复 | 问题修复 |
| `refactor` | 重构 | 代码重构 |
| `perf` | 性能优化 | 性能优化 |
| `style` | 样式调整 | 样式调整 |
| `docs` | 文档更新 | 文档更新 |
| `test` | 测试相关 | 测试 |
| `ci` / `build` | 构建/CI | 工程化 |
| `chore` | 杂项 | 其他 |
| 无前缀 | 未分类 | 其他 |

如果某个类型下没有提交，直接跳过，不要输出空分组。

**跳过 merge commit**：message 以 "Merge" 开头的提交不计入统计。

### 3. 生成报告

将报告写入 `daily/` 目录（位于当前 git 仓库根目录下），文件名格式为 `YYYY-MM-DD.md`（周报为 `YYYY-MM-DD-week.md`）。目录不存在则创建。

#### 日报格式

按类型分组，每条条目标注责任人：

```markdown
# 工作进展 — YYYY-MM-DD（周X）

> 统计：N 个提交，涉及 M 个分支，P 位贡献者

- **新功能**
  - 实现用户登录页面的表单和校验功能 (@sunweiwei)
  - 新增数据导出为 CSV 功能 (@zhang)

- **问题修复**
  - 修复移动端列表滚动卡顿 (@li)

- **代码重构**
  - 将认证逻辑从组件抽离为独立 service 模块 (@sunweiwei)
```

#### 周报格式

结构与日报相同，标题和时间范围调整：

```markdown
# 本周总结 — MM/DD ~ MM/DD（第N周）

> 统计：N 个提交，涉及 M 个分支，P 位贡献者

- **新功能**
  - ...（@xxx）

- **本周亮点**
  - （从本周工作中提炼 2-3 个关键成果，跨团队视角）
```

### 4. 总结要求

对 commit message 的总结应做到：

- **合并同类项**：同一功能的多次提交合并为一条描述（如 "feat: add login form" + "feat: add login validation" → "实现了登录页面的表单和校验功能"）
- **去技术化**：将实现细节转化为业务语言（如 "refactor: extract useAuth hook" → "重构了认证逻辑，提升代码可维护性"）
- **保持简洁**：每条总结控制在一行以内，不要在末尾标注分支名
- **责任人格式**：每条末尾加 `(@作者名)`，多人共同完成同一功能时列出所有人 `(@a, @b)`

### 5. 特殊情况

- **没有提交**：输出 "该时间段内没有提交记录。"
- **多仓库**：如果用户想查看其他仓库，提示用户先切换到目标仓库目录
